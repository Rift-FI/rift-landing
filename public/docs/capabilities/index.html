Capabilities

Every capability group in the Rift API, what it does, the main endpoints and where to read more.

Rift Wallets gives each customer a smart account owned only by their passkeys, with gas handled for them, and payment rails built in. Rift holds no key that can move a customer's funds. This page maps each capability group to the endpoints you call with your project API key, your platform key or your project id. Flows that belong to the signed-in end user (passkeys, device binding, approvals, balances, sending, payouts, onramp, KYC pages) are run by the Rift widget, the React components and the SDK on the customer's behalf; they are listed separately at the end. Every endpoint can be tried in the API playground.

Beta features may change before general availability.

Run by the widget, React components and SDK

These are the end user's own flows. They are authenticated with the customer's access token rather than your project key, and several need a passkey signature that only the customer's device can produce, so the Rift widget or SDK calls them for you. They are not part of the per-project API reference; the operation pages are collected under Used by the Rift widget and app.

  • Customer profile, balances, history, deposits, sending and signing (two-phase preview then submit), approvals, trusted devices, passkey registration.
  • Payouts (offramp), onramp, beneficiaries, bridges, WalletConnect, ledger and statements, identity verification pages.

Supported money rails

Payouts and onramp cover Kenya (KES), Nigeria (NGN), Tanzania (TZS), Uganda (UGX), Ghana (GHS) and Malawi (MWK), with mobile money, bank, till and paybill depending on the country. Availability changes during the day: always read GET /v1/payouts/countries (public, no authentication) rather than hard-coding a list. Details and per-transaction limits: Corridors and limits.

Chains

Wallets have the same address on every supported chain. Read GET /v1/chains and GET /v1/chains/{chainId}/tokens for the live list.

Platform conventions

  • Errors: { "error": "CODE", "message": "..." }. See errors.
  • Fund-moving one-phase calls return 202 APPROVAL_REQUIRED unless the request already carries a passkey proof.
  • Money statuses use one vocabulary: awaiting_payment, processing, completed, refunding, refunded, expired, cancelled, failed.
  • Lists page with cursor and nextCursor; date filters are inclusive ISO 8601.
  • Limits: see rate limits.
